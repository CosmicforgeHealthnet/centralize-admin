# Advertising Execution audit-event catalogue

Immutable audit actions implemented: `EXECUTION_PLAN_CREATED`, `EXECUTION_PLAN_UPDATED`, `EXECUTION_PLAN_VALIDATED`, `EXECUTION_PLAN_SUBMITTED`, `EXECUTION_APPROVED`, `EXECUTION_REJECTED`, `EXECUTION_REVOKED`, `EXECUTION_QUEUED`, `EXECUTION_STARTED`, `EXECUTION_COMPLETED`, `PROVIDER_OPERATION_ATTEMPTED`, `PROVIDER_OPERATION_SUCCEEDED`, `PROVIDER_OPERATION_FAILED`, `PROVIDER_OPERATION_UNKNOWN`, `EXECUTION_DRIFT_DETECTED`, `EXECUTION_DRIFT_ACKNOWLEDGED`, `EXECUTION_COMPENSATION_CREATED`, `EXECUTION_OVERRIDE_USED`, `EXECUTION_OPERATION_RETRY_REVIEWED`, policy/kill-switch, reconciliation, creative revision/review and dead-letter actions. Queue, retry, compensation and override-use actions are written inside their authoritative transaction; provider-attempt evidence is persisted before mutation and terminal evidence after result classification.

Evidence is bounded to actor, target identifiers, exact plan version/fingerprint, provider/account safe scope, decision/reason, counts, hashes, sanitized provider request ID, outcome category, timing, changed field paths and correlation context when supplied. Full before/after objects, credentials, native bodies, authorization headers, developer tokens, signed URLs, internal paths and lease owners are prohibited.

Database triggers prevent update/delete of approval rows/events, policy history, validation packets/issues, state snapshots, reconciliations, drift acknowledgments and retry reviews. The remediation migration also protects the central `admin_audit_logs` table from UPDATE and DELETE. Rejection and revocation append evidence; corrections use new linked evidence. No API exposes audit-row mutation.
